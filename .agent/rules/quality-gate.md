# Quality Gate

## 强制规则
- 在**任何**代码变更（新增、修改、删除）之后，**报告“完成”之前**，必须调用 MCP 工具 `quality_fix`。
- 如果 `quality_fix` 报告剩余问题，必须继续修复，直到它通过或你明确说明为什么某个问题无法修复。
- **禁止**在未调用 `quality_fix` 的情况下说“已完成”“Done”“可以部署了”。

## 修复优先级
1. `quality_fix` 自动修复的问题 → 接受修复结果。
2. 剩余的 lint/format 错误 → 逐条修复，不要忽略。
3. 如果某个错误需要架构级调整，先向用户说明，不要擅自大改。

## 边界
- 不要为了让 `quality_fix` 通过而删除有实际功能的代码。
- 如果 `quality_fix` 本身执行失败（超时、MCP 断开），告知用户并建议手动运行 `npx eslint --fix .` 作为兜底。
- 若报错的根本原因属于历史遗留代码且不在本次任务改动范围内，严禁擅自扩大修改面，仅在汇报中向用户说明该报错属于外部/历史代码即可。
